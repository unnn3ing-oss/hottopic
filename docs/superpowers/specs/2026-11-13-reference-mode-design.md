# 參考模式設計（精簡版）

日期：2026-11-13　狀態：待確認

## 目的與背景

小編在挑新聞、想改標時，常要對照「別人是怎麼改這則標題的」。現有熱門新聞庫只收「自己要用的文章」（多版改標、小編文、使用次數、到期日），沒有地方收別人的改標。

**參考模式**：同一個網頁頂欄切換，收集「某人對某篇新聞發過的改標」，之後能依「人」或「主題分類」快速回頭看。

## 目標

- 頂欄可在「新聞庫」與「參考」之間切換；參考模式有列表、搜尋、排序、分頁與新增／編輯／刪除。
- 新增流程與現有一致：貼網址 → 自動抓原標（失敗冷卻 5 秒重試一次、可按「重新讀取」）→ 自動依網址猜主題分類。
- 每筆資料 = **一個人對一篇文章的一個改標**，欄位：原標（自動抓、建立後不可改）、改標（一個）、參考誰、主題分類、原文網址。
- 同一篇文章可以有多筆（不同人各一筆）；卡片上能對照「同一篇其他人的改標」。
- 兩排篩選：**人**（全部＋每個人）與**分類**（全部＋各主題），可同時使用（取交集）。
- **班段記憶**：新增時第一個選或寫的人，成為本班預設人選，直到交班自動失效（見下）。

## 非目標

- 參考模式沒有小編文、使用次數、使用時間、到期日、「直接產圖」「標記已使用」。
- 沒有人員管理頁：人名清單由既有資料推導，不能批次改名（打錯要逐筆編輯）。
- 不做帳號系統；班段預設只存在這台裝置的瀏覽器，不跨裝置同步。
- 不搬移、不改動現有新聞庫資料。

## 反目標（即使功能能用也算失敗）

- 新聞庫模式的任何行為、資料、畫面有退步。
- 參考資料混進正式新聞列表、分類計數或搜尋結果。

## 畫面草圖（參考模式）

```

人    [全部 42] [小明 15] [小華 9] [阿美 18]
分類  [全部 42] [社會 20] [生活 8] [健康 6] …
共 15 則・第 1／1 頁                       排序：最新 ▾   顯示：20 則 ▾
┌──────────────────────────┐ ┌─────────────────────────────────────┐
│ 改標：爆！他一句話讓全場… │ │ 參考 #R12   小明   社會              │
│ 小明 · 社會 · R12         │ │ 原始  原標標題文字…                  │
│ 改標：…                   │ │ 改標  （小明）爆！他一句話讓全場…    │
└──────────────────────────┘ │ 同一篇其他人的改標                    │

                              └─────────────────────────────────────┘
```

新增視窗欄位（由上到下）：分類、參考誰（可選可寫，下拉是既有人名）、原始標題（＋重新讀取、狀態膠囊）、原文網址、改標。

## 資料與後端

- 試算表新增分頁 **「參考」**，欄位：`id`、`分類`、`原始標題`、`原文連結`、`改標`、`參考誰`、`建立時間`。分頁由後端首次讀取時自動建立（與現有分頁相同的做法）。
- 編號：`R` + 流水號（R1、R2…）。因為同網址可以多筆，不能再用網址數字當編號。
- 主題分類**共用**現有「分類」分頁的清單。
- 人名清單：從「參考」分頁的「參考誰」去重推導，不另開分頁。
- 新動作（Apps Script，`ACTIONS` 新增）：`listRefs`、`addRef`、`updateRef`、`deleteRef`；`fetchTitle` 直接沿用。Worker 原樣轉送動作，**不用改、不用重新部署**；Apps Script 要「管理部署作業 → 新版本」。
- 驗證：改標必填（≤500 字）、參考誰必填（≤30 字，去頭尾空白與換行）、原標與網址沿用現有規則、分類必須在清單內。寫入一律包在 `withLock_` 內，沿用現有整塊寫入與文字格式做法。
- **重複判斷**：「同一篇文章」＋「同一個人」視為重複，回 `duplicate` 並附既有那筆，網頁提示「改為編輯這則」。「同一篇文章」的判斷沿用現有編號規則（網址最長數字，沒有數字則比整個網址）。同篇不同人則允許。
- 後端還沒更新時，`listRefs` 會回 `bad_request`；網頁在參考模式顯示「後端還沒更新，請重新部署（見 README）」，不當成一般載入失敗。

## 前端

- 同一頁、同一份 `app.js`：新增 `state.mode`（`lib`／`ref`）。切到參考模式時第一次載入參考資料，之後沿用已載入的資料；新增／編輯／刪除後更新本地資料。模式記在 localStorage（失敗就不記）。
- 列表、分頁（`paging.js`）、排序與顯示則數選單、搜尋框沿用；搜尋範圍：改標、原標、參考誰、編號。排序：最新（預設）、最舊。
- 兩排篩選的數字互相連動（人那排的數字依目前分類算，分類那排依目前選的人算）。
- 新增／編輯視窗沿用同一個 `<dialog>`，依模式隱藏「改標多版、小編文、使用狀態、到期日」，顯示「參考誰」與單一「改標」。編輯時原標與網址唯讀，與現有一致。
- 新增視窗的即時提示：同一篇已有哪些人的改標（資訊提示）；同篇同人已存在時顯示「改為編輯這則」。
- 所有文字以 `textContent` 輸出，CSP 不變（人名下拉用 `<datalist>`，不需放寬）。

## 班段記憶

- 班段：台北時間 **00:00–08:00、08:00–16:00、16:00–24:00**，交班點 00:00、08:00、16:00。純函式 `shiftKey(ms)`（放 `lib.js`，可測）回傳「台北日期＋第幾個班」。
- 存在 localStorage：`{ who, shift }`。開啟「新增參考」時，若存的 `shift` 等於現在的 `shiftKey`，就預填 `who`；已跨班就視為沒有並清掉。
- **記錄時機**：本班第一次「新增參考」**成功儲存**時，記下當時填的人（不是打到一半就記，避免記下打錯的名字）。
- 之後每篇仍可手動改人，改了**不影響**本班預設。視窗裡顯示「本班預設：小明」，輸入的人與預設不同時出現小按鈕「設為本班預設」，打錯第一個人時有出口。
- 編輯既有資料不套用預設。

## 限制

- `lib.js` 限制不變（Apps Script 與瀏覽器共用，ES2019、不用 `window` 等）。
- 不引入新依賴；測試沿用 `node --test` 與 Playwright 冒煙測試（假 API 需補上新動作）。
- README 需補：參考模式說明、「這個版本後端要重新部署新版本」。

## 我自己做的決定（請檢查）

1. 交班點用 00:00／08:00／16:00（台北時間），夜班 00:00–08:00 也算一個班段。
2. 班段預設人選在「第一次成功儲存」時記下；之後可逐篇改，並有「設為本班預設」按鈕。
3. 同篇同人視為重複會擋下；同篇不同人允許。
4. 主題分類與新聞庫共用同一份清單。
5. 人名由資料推導，沒有管理頁、不能批次改名。
6. 參考模式不含小編文、使用狀態、到期日、直接產圖。
7. 參考資料不刪除前會一直保留，沒有到期機制。
8. 切換模式後，下次開頁面會記住上次的模式。

## 留給實作者

- 新增視窗要重用還是抽出共用函式（自動抓標題、冷卻重試邏輯已存在於 `app.js`）。
- 手機版頂欄怎麼放模式開關、兩排篩選列在窄螢幕的樣式。
- 兩排篩選數字連動的實作與效能（資料量預期在數百筆內）。
- 測試：`shiftKey` 單元測試（含跨日與邊界時刻）、後端 `addRef`／`updateRef`／`deleteRef`／重複判斷、前端冒煙測試。
