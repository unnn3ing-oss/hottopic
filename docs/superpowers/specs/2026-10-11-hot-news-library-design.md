# 熱門新聞庫 設計 Spec

日期：2026-10-11　狀態：已核准（2026-10-12，使用者回覆「規格 OK」）

## 1. 目的與使用者

- **使用者**：單一使用者（社群小編本人）。
- **目的**：把挑好的熱門新聞集中管理，每則記錄原文連結、改過的標題、小編文，以及「上次什麼時候用來發文、用過幾次」，讓挑題時一眼看出哪些很久沒用、哪些剛用過。
- **成功標準**
  1. 能手動新增、編輯新聞，並看到完整保留換行的改標標題。
  2. 每則都有「複製標題」「複製留言」，換行與格式不跑掉。
  3. 能標記已使用，並看到上次使用時間與使用次數。
  4. 資料存在使用者自己的 Google 雲端硬碟，不公開。

## 2. 範圍

**包含**：新聞列表（搜尋、分類篩選、排序）、新增、編輯、刪除、複製標題、複製留言、標記已使用、貼網址自動帶入原始標題、分類清單維護（在試算表內）。

**不包含**（YAGNI）：自動撈新聞、多人協作、使用紀錄歷史、冷卻天數與顏色警示（使用者已明確不要）、垃圾桶／復原刪除（誤刪時用試算表的版本記錄還原）、瀏覽器外掛一鍵加入（僅在伺服器端抓標題也被擋時才另案考慮）。

## 3. 已確認的決策

| 項目 | 決定 |
|---|---|
| 儲存 | 私人 Google 試算表（使用者雲端硬碟），不公開、不用 SQL |
| 介面與後端 | Google Apps Script Web App，以部署者身分讀寫，存取限本人 |
| 編號 | 取網址中最長的一串數字；重複編號視為已存在 |
| 複製留言格式 | `小編文` 換一行 `https://news.tvbs.com.tw/news/編號`（不空行） |
| 時間與次數 | 只在按「標記已使用」時更新；次數 +1 |
| 多版改標 | 一則新聞可有多個改標，用左右滑動切換；使用紀錄同時記在整則新聞與被標記的那一版（預設做法，待使用者確認） |
| 小編文 | 整則新聞共用一份，不隨改標版本變化（預設做法，待使用者確認） |
| 自動抓標題 | 要。瀏覽器網頁直接 `fetch` 已實測被 TVBS 的 CORS 擋下，所以改由 Apps Script 伺服器端抓取，已實測可取得 TVBS 文章的 `og:title`（HTTP 200）；解析沿用使用者外掛的做法（讀 meta、依序找標題來源），不用 AI、爬蟲 API 或第三方中繼；抓不到就手動輸入（細節見 §5） |
| 預覽 | 互動預覽（含多版改標、刪除）：https://claude.ai/artifact/QegKJLLiAjEfG1R1qwsHU9 |

## 4. 資料模型（試算表）

### 分頁「新聞」（第 1 列為標題列，一列一則）

| 欄 | 欄位 | 說明 |
|---|---|---|
| A | `id` | 網址數字；抓不到數字時為 `N` 加流水號 |
| B | `分類` | 必填，值來自「分類」分頁 |
| C | `原始標題` | 必填，建立後 UI 不可改 |
| D | `原文連結` | 必填 |
| E | `小編文` | 可空白，可含換行；整則新聞共用一份 |
| F | `上次使用時間` | 整則新聞的總計，空白代表從未使用 |
| G | `使用次數` | 整則新聞的總計，整數，預設 0 |
| H | `建立時間` | 自動 |

### 分頁「改標」（一列＝一則新聞的一個改標版本）

| 欄 | 欄位 | 說明 |
|---|---|---|
| A | `新聞id` | 對應「新聞」分頁的 `id` |
| B | `版本號` | 該則新聞內遞增的流水號，同時決定左右滑動的順序 |
| C | `標題` | 可含換行，必填（空白版本不儲存） |
| D | `上次使用時間` | 該版本的最近使用時間，空白代表未用過 |
| E | `使用次數` | 該版本被標記使用的次數，預設 0 |
| F | `建立時間` | 自動 |

一則新聞可有 0 個、1 個或多個改標版本。整則新聞的「上次使用時間」「使用次數」是所有版本的總計，每次標記時一起更新。

### 分頁「分類」
單欄清單，預設：社會、生活、健康、政治、國際、娛樂。使用者在試算表增刪即同步到介面。

### 時區
專案時區設為 `Asia/Taipei`，時間以試算表日期格式儲存，畫面顯示 `yyyy/MM/dd HH:mm`。

## 5. 功能行為

### 列表
- 每則顯示：`#編號`、分類、**改標區（完整顯示、保留換行）**、小編文（最多 3 行）、整則新聞的上次使用時間與「N 天前」、總使用次數。
- **原始標題預覽與「原文」連結在同一排**，位於卡片最下方、與四個操作按鈕同排：`[原始] 標題（單行，過長以 … 截斷，滑鼠停留顯示全文）　原文 ↗`。畫面太窄放不下時，這一組整個換到下一行，仍保持並排。
- **改標區是可左右滑動的輪播**，有多版時顯示圓點、‹ › 按鈕與「第 N / M 版」，每一版下方顯示該版本自己的上次使用時間與次數。可用以下方式切換，一次動作只換一版：
  - 手機、平板：手指左右滑動（瀏覽器原生捲動並自動對齊）。
  - 電腦滑鼠：在改標區**按住左鍵左右拖曳**，拖過約 15%（最多 60px）就換版，沒拖過則彈回；拖曳時不會選取文字。
  - 觸控板或橫向滾輪：橫向滑動換一版；以直向為主的滾動仍交給頁面捲動。
  - 鍵盤：焦點在改標區時按 ← / →。
  - 只有一個版本的新聞不顯示輪播控制，也不能拖曳。
- 預設顯示第 1 版；重新整理列表（搜尋、篩選、標記後）時，每則會停留在使用者上次看的那一版。
- 沒有任何改標的新聞顯示「（尚未改標）」，「複製標題」停用。
- 搜尋範圍：編號、原始標題、所有改標版本、小編文。
- 排序：最久未用優先（預設，從未使用者排最前）、最近使用優先、使用次數多到少、最新新增。
- 分類篩選：全部 + 各分類，並顯示筆數。

### 新增
1. 貼上原文網址，系統抽出編號並檢查重複；重複時顯示提示並可一鍵轉為編輯該則。
2. 自動帶入原始標題（見下），使用者可修改；選分類；改標標題與小編文可稍後補。
3. 必填：網址、原始標題、分類。

### 編輯
編號、網址、原始標題唯讀；分類、小編文可改。改標區是一個清單：每個版本一個輸入框，可「＋ 新增一個改標」或「移除這版」（只剩一版時不顯示移除）。按「儲存」才一次寫入，按「取消」全部放棄；空白版本在儲存時自動略過。已存在版本的使用紀錄會保留。

### 刪除
- 入口在「編輯」視窗左下角的「刪除這則」，列表上不放刪除鈕，避免誤觸。
- 第一次按變成紅底「再按一次刪除（無法復原）」，4 秒內再按才生效；逾時恢復原狀。
- 伺服器端在鎖內依 `id` 找到該列並刪除整列，同時刪除「改標」分頁中屬於該則的所有版本；找不到時回傳「這則已不存在」，畫面重新整理列表。
- 刪除是永久的，不做垃圾桶。誤刪可在 Google 試算表的「版本記錄」還原。

### 複製標題
把**目前顯示的那一版**改標原樣（含換行）寫入剪貼簿。有多版時提示「已複製第 N 版標題」。

### 複製留言
輸出 `小編文 + "\n" + "https://news.tvbs.com.tw/news/" + id`。小編文為空時只輸出網址。若 id 是 `N` 開頭（網址沒有數字），網址改用該則的原文連結。

### 標記已使用
按第一下按鈕變為「再按一次確認」（有多版時註明「第 N 版」），3 秒內再按才生效；期間若滑到別的版本，確認狀態取消。伺服器端在鎖內同時更新：整則新聞的 `上次使用時間` 設為現在、`使用次數` +1，以及**目前顯示那一版**的 `上次使用時間` 與 `使用次數`。沒有任何改標的新聞只更新整則新聞。回傳更新後的新聞與其所有版本。

### 自動抓標題

**實測結論（2026-10-11）**：使用者在 `https://example.com` 的瀏覽器 Console 對 `https://news.tvbs.com.tw/cars/4032757` 執行 `fetch`，得到 `blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource`（網站回應 HTTP 200，但沒有允許跨網站讀取的標頭）。因此**任何一般網頁（包含 Apps Script 的網頁）都無法在瀏覽器端直接讀取 TVBS 文章**；使用者的外掛抓得到，是因為外掛有額外的網站存取權。瀏覽器端 `fetch` + `DOMParser` 這條路不納入設計。

**伺服器端實測結論（2026-10-12）**：使用者在自己的 Apps Script 編輯器以 `UrlFetchApp.fetch` 抓同一篇文章（帶一般瀏覽器 `User-Agent`、`Accept-Language: zh-TW`、`muteHttpExceptions: true`），結果 `status=200`、內容長度 215,916 字元，並用規則運算式取得 `<meta property="og:title" content="買二手車別只看外觀、里程數！「4大陷阱」小心、這些地方要檢查">`。確認：
- Apps Script 伺服器端**抓得到** TVBS 文章，沒有被防機器人頁面攔下（這一次）。
- `og:title` 這一篇**沒有網站名稱後綴**；標題含全形標點（`！`、`「」`、`、`），沒有 HTML 實體。
- meta 屬性順序是 `property` 在前、`content` 在後（解析仍不依賴順序，因為其他網站可能相反）。
- 整頁約 216 KB，但標題在 `<head>`，只需解析 `<head>` 範圍。

**做法：由 Apps Script 伺服器端抓取，解析沿用外掛的邏輯**

1. `Code.gs` 的 `fetchTitle(url)` 用 `UrlFetchApp.fetch` 下載原始碼：`muteHttpExceptions: true`、跟隨轉址、帶一般瀏覽器的 `User-Agent` 與 `Accept-Language: zh-TW`，以 UTF-8 解碼。`<meta>` 與 `<title>` 只看 `</head>` 之前的內容（找不到 `</head>` 時取前 300 KB）；`<h1>` 在內文，取前 300 KB 內的第一個。
2. 解析（Apps Script 沒有 `DOMParser`，改用規則運算式）：找出所有 `<meta>` 標籤並讀取屬性（不依賴屬性順序，單雙引號皆可），依序找標題來源，取第一個非空值，並還原 HTML 實體（`&amp;`、`&quot;`、`&#39;`、數字實體）。
   - **來源順序（預設，待使用者的外掛順序確認）**：`og:title`（TVBS 已實測有值）→ `twitter:title` → `<title>` → 第一個 `<h1>`。
3. 清理：去除前後空白、把連續空白與換行壓成單一空白；去除結尾的網站名稱後綴，格式為「分隔符號（`｜`、`|`、`-`、`–`、`—`）＋已知網站名稱」，已知名稱清單（`SITE_SUFFIXES`）寫在 `lib.js`。沒有符合已知名稱的後綴就不動，以免誤刪標題本身的內容。實測的 `og:title` 沒有後綴，所以這一步對 TVBS 的 `og:title` 是空操作，主要保護退回 `<title>`／`<h1>` 時的情況；`<title>` 的後綴格式待使用者提供實際標記後再補進清單，不先猜。
4. 前端收到結果後帶入「原始標題」，標示來源（例如「來自 og:title」），使用者可直接修改。

**失敗處理**：狀態碼不是 200、抓取丟出例外、回傳的是驗證或防機器人頁面（標題為「Just a moment…」之類）、找不到任何標題來源時，回傳空值並提示「抓不到標題，請手動輸入」，不阻擋儲存。`UrlFetchApp` 沒有提供逾時選項，所以「8 秒」改由前端計時：等超過 8 秒就放棄並顯示同樣的提示，晚到的結果丟棄、不覆蓋使用者已輸入的內容。只允許 `http`／`https` 網址。非 UTF-8 的網頁可能亂碼，需手動修正。

**備案（目前不做；只有日後伺服器端常被 TVBS 擋下時才另案討論）**：沿用使用者現有的外掛，在文章頁一鍵把網址與標題送進熱門新聞庫，或讓外掛代為抓取後回傳給網頁。這需要外掛的程式碼，不在本次範圍內。

```

### 檔案（repo）
```
src/
  appsscript.json   時區 Asia/Taipei；webapp: executeAs USER_DEPLOYING, access MYSELF
  Code.gs           doGet、listItems、addItem、updateItem、markUsed、deleteItem、fetchTitle
  lib.js            純函式與常數：extractId、buildComment、cleanTitle、normalizeUrl、titleFromHtml（規則運算式版）、TITLE_SOURCES、SITE_SUFFIXES（也可被 node 測試載入）

### 單元職責
- `lib.js`：不碰 Google API 的純邏輯，可獨立測試。
- `Code.gs`：唯一接觸試算表與外部網址的地方；每個對外函式檢查輸入並回傳 `{ ok, data | error }`。
- `index.html`：只負責呈現與呼叫 `google.script.run`，不含資料規則。

## 7. 錯誤處理與一致性

- **併發**：所有寫入使用 `LockService.getScriptLock()`（等待 10 秒），逾時回傳「系統忙碌，請重試」。
- **重複編號**：伺服器端再次檢查，回傳錯誤與既有列，UI 轉為編輯。
- **輸入驗證**：必填欄位、網址格式、分類必須存在於清單，伺服器端與前端都驗證。
- **剪貼簿**：先用 `navigator.clipboard.writeText`，失敗時退回隱藏 `textarea` + `execCommand('copy')`；仍失敗則提示手動選取。
- **失敗呈現**：所有伺服器錯誤以畫面內訊息顯示，不使用 `alert`。

## 8. 安全與隱私

- 試算表維持私人；Web App 只允許本人存取，以本人身分執行。
- 自動抓標題只取純文字標題：伺服器端以規則運算式讀取，不執行網頁內容；回給前端的只有一段文字，前端一律以 `textContent` 或轉義後輸出，不把網頁內容當 HTML 插入畫面。
- 不儲存任何金鑰；不使用外部資料庫。

## 9. 測試策略

- **單元測試（node:test）**：`extractId`（含 `cars/4032757`、多段數字、無數字、帶 query 的網址）、`buildComment`（有／無小編文、`N` 開頭編號）、`cleanTitle`（各種後綴、全形與半形分隔符號、標題本身含 `｜` 時不誤刪）、`normalizeUrl`、`titleFromHtml`（`og:title` 優先並依序退回、屬性順序顛倒的 meta、單雙引號、HTML 實體、前後空白與換行）。`<head>` 之外的假標籤不誤判。另加入使用者實測取得的 **TVBS 真實標記**作為測試資料（`test/fixtures`）：`<meta property="og:title" content="買二手車別只看外觀、里程數！「4大陷阱」小心、這些地方要檢查">`，預期解析結果與原文完全相同（含全形標點、無後綴被誤刪）；若使用者再提供 `<title>`／`<h1>` 的實際標記，一併加入。
- **手動驗證清單**（部署後在實機執行）：新增／重複／編輯／刪除（含逾時取消、刪除後列表更新）／標記已使用／兩種複製（含換行貼到 IG、Threads 檢查）／自動抓標題成功與失敗／手機版面。
- **輪播互動測試（Playwright + Chromium）**：載入 `index.html`（以假資料取代 `google.script.run`），驗證手指（逐點觸控事件）、滑鼠拖曳、橫向滾輪、鍵盤、按鈕五種切換方式都能換到正確版本並對齊，拖曳不選取文字，直向滾輪不誤換版，以及桌面與手機寬度的版面（無橫向溢出、原始標題與「原文」同排）。預覽版已用同一套測試驗證 23 項。
- **`Code.gs` 的自動化測試**：Apps Script 無法在本機執行，改在 node 內以假的 `SpreadsheetApp`／`LockService`／`UrlFetchApp` 載入 `lib.js` + `Code.gs`，測試新增、編輯、刪除連帶改標、標記已使用、重複編號、鎖逾時、抓標題各情境；前端 e2e 測試也接這個後端，等於整條流程（畫面 → `google.script.run` → `Code.gs` → 假試算表）都有測。假物件與真實 API 的差異（日期型別、純文字格式、`appendRow` 行為、剪貼簿權限）仍由手動驗證清單覆蓋。

## 10. 已知風險與待驗證

1. **Apps Script 伺服器端抓 TVBS 標題的穩定度**：已實測一次成功（HTTP 200、取得 `og:title`）。尚未確認的是長期穩定度：TVBS 或其防護日後可能對來自 Google 的請求出現驗證頁、限流或封鎖，且測試是在編輯器內執行，部署後的 Web App 尚未實測（兩者使用相同的 Google 伺服器環境，預期一致）。Claude 的執行環境連 TVBS 會被網路代理擋下，無法代為重測。被擋時退回手動輸入，不影響其他功能。
2. **Apps Script 網頁內的剪貼簿權限**：HTML Service 在 iframe 內，`navigator.clipboard` 可能被限制，已設計 `execCommand` 退路，需在實機驗證。
3. **部署需要使用者操作**：Claude 在此環境無法登入使用者的 Google 帳號，部署（`clasp push` 或手動貼入 Apps Script 編輯器）與授權由使用者完成，我會提供逐步說明。
4. **效能**：資料量預期為數百到數千列，整表讀取即可；若超過約 5,000 列再考慮分頁。
